# Marketing Service

> **Public marketing landing page** — a fully static Astro site served by a small Bun static-file server. No data-layer access of any kind.

---

## Overview

| Property              | Value                                     |
| --------------------- | ----------------------------------------- |
| **Runtime**           | Bun 1.3.14-alpine (shared base toolchain) |
| **Framework**         | Astro (static output)                     |
| **Container Port**    | 8080                                      |
| **Staging Host Port** | 8082 (`MARKETING_PORT`)                   |
| **Replicas**          | `MARKETING_REPLICAS`                      |
| **Network**           | `backend` only                            |
| **Environments**      | Staging, Prod                             |

---

## Multi-Stage Dockerfile

The image builds from `app/marketing/Dockerfile` using the **monorepo root as the build context**, so manifest, source, and entrypoint paths are repo-relative:

```dockerfile
# Stage 0 (base): Bun 1.3.14 + pnpm, runtime tooling, non-root appuser (1000:1000)
# Stage 1 (builder): pnpm install --filter @abugida/marketing --frozen-lockfile,
#                    then astro build for a fully static dist/ output
# Stage 2 (runtime): static dist/ + Bun static-file server
CMD ["bun", "server.mjs"]
```

Only the static build output ships in the runtime image — no `node_modules`, lockfiles, or build tooling. The container runs as a non-root user (`appuser`, uid/gid 1000).

## Dependencies

| Service                  | Connection | Purpose                          |
| ------------------------ | ---------- | -------------------------------- |
| OTEL Collector (`:4317`) | gRPC       | Metrics, traces, and logs export |

The Marketing service has **no database, cache, or vault dependencies** — the output is fully static. It declares no `depends_on` entries and attaches to the `backend` network only; it is never dual-attached to `infrastructure`.

## Health Check

The service exposes a `/health` endpoint confirming the Bun static server is accepting connections. Docker probes it via `curl -sf http://localhost:8080/health`; with no upstream dependencies, a short `start_period` suffices.

---

## Deployment Topology

| Environment | Replicas                    | Port Exposure                         | Ingress                                          |
| ----------- | --------------------------- | ------------------------------------- | ------------------------------------------------ |
| Staging     | `MARKETING_REPLICAS`        | `${MARKETING_PORT:-8082}:8080` (host) | Direct access for validation                     |
| Prod        | Scaled via replica settings | None published                        | Via Caddy on its own domain (`DOMAIN_MARKETING`) |

Container names are auto-generated by Compose (`infra-marketing-1` style) rather than fixed names, so upstream discovery relies on Compose service DNS (`marketing:8080`).
